Do GTM connector first → intelligence foundation → remaining connectors.
Best sequence:
1. Build GTM connector
   - PostgreSQL → PostgreSQL / your first target path
   - stable connector capability contract
   - schema discovery
   - type discovery
   - preflight checks
   - telemetry emission

2. Build intelligence foundation
   - LLM provider governance
   - MCP/tool access layer
   - intelligence capability registry
   - admin-only config
   - agent boundary rules

3. Prove intelligence on GTM connector
   - explain preflight failures
   - explain topology
   - recommend mappings
   - summarize telemetry
   - risk analysis

4. Add remaining connectors
   - each connector registers capability pack
   - no core intelligence rewrite
Do not wait to add all connectors before intelligence. That delays learning too much.
Do not build intelligence before at least one real connector. Otherwise you’ll design against abstractions only.
Correct product strategy:
One real connector proves the contract.
Intelligence proves extensibility.
Remaining connectors plug into the registry.
So roadmap:
v0.2 / GTM
GTM connector + deterministic execution

v0.6.0
Intelligence foundation

v0.6.1
MCP/tool access + registry

v0.6.2+
Agent capabilities proven on GTM connector
