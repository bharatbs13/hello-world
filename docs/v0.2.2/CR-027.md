# CR-027 — Remote UAT Artifact Deployment

## Status

Proposed for v0.2.2

## Objective

Enable RXTA to deploy only the UAT artifacts required for execution to the Relix VM. The complete RXTA repository shall never be deployed or synchronized to the Relix VM.

---

## Motivation

The Relix VM is a runtime environment.

RXTA is an orchestration and validation framework executed from the Relix Tools VM.

Historically, portions of the RXTA repository were copied to the Relix VM to execute mock database setup and other UAT helper scripts. This creates unnecessary coupling between the runtime environment and the validation framework.

The runtime VM should receive only the artifacts required to prepare and validate the selected UAT execution.

---

## Owns

* remote UAT artifact packaging
* artifact deployment
* remote script execution
* artifact cleanup
* deployment manifest generation

---

## Does Not Own

* Relix runtime deployment
* Relix application source code
* RXTA source synchronization
* Git repository management on the Relix VM

---

## Required Architecture

```text
                 Relix Tools VM
        +--------------------------------+
        | RXTA                           |
        |                                |
        | relix-deploy                   |
        | UAT catalogs                   |
        | UAT orchestration              |
        | artifact packaging             |
        +---------------+----------------+
                        |
                        |
                Deploy selected artifacts
                        |
                        v
             +------------------------+
             | Relix VM               |
             |                        |
             | Relix runtime          |
             | PostgreSQL             |
             | Temporary UAT scripts  |
             | Temporary mock DB data |
             +------------------------+
```

The complete RXTA repository shall remain on the Relix Tools VM.

Only the required deployment artifacts are transferred to the Relix VM.

---

## Deployment Model

Examples of deployable artifacts include:

* mock database setup scripts
* mock data files
* storage initialization scripts
* cleanup scripts
* database migration helpers
* runtime configuration templates
* temporary SQL files

Artifacts shall be copied to a temporary working directory on the Relix VM, executed, and optionally removed after successful completion.

---

## Requirements

The deployment framework shall:

* package only required artifacts for the selected execution profile
* transfer only those artifacts to the Relix VM
* execute artifacts remotely
* report execution status
* support idempotent execution where practical
* optionally clean temporary deployment artifacts after execution

The deployment framework shall **not**:

* synchronize the RXTA repository
* clone the RXTA repository
* require Git on the Relix VM for RXTA
* execute RXTA directly from the Relix VM

---

## Benefits

* clear separation of responsibilities
* smaller deployment footprint
* reduced runtime dependencies
* improved security
* simpler runtime environment
* deterministic UAT deployment
* independent evolution of RXTA and Relix

---

## Acceptance Criteria

* No RXTA repository is deployed to the Relix VM.
* Mock database deployment succeeds using packaged artifacts only.
* Real database deployment uses the same artifact deployment mechanism.
* UAT helper scripts execute remotely without requiring RXTA on the Relix VM.
* Temporary artifacts can be removed after execution.
* Existing UAT workflows continue to function without repository synchronization.
