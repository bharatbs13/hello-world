# CR-027 — Remote UAT Artifact Deployment

## Status

Approved for v0.2.2

---

# Objective

Define the deployment architecture for RXTA UAT artifacts by deploying only the resources required for a selected UAT execution to the Relix VM.

The complete RXTA repository shall remain on the Relix Tools VM and shall never be synchronized or deployed to the Relix VM.

RXTA shall package only the required deployment artifacts, transfer them to the target environment, execute them remotely, and optionally remove them after execution.

---

# Motivation

The Relix VM is a runtime environment responsible for hosting the Relix application and supporting services.

RXTA is an orchestration and validation framework executed from the Relix Tools VM.

Previous deployment approaches synchronized portions of the RXTA repository to the Relix VM in order to execute storage setup scripts and UAT helpers. This unnecessarily coupled the runtime environment with the validation framework.

The runtime environment should receive only the artifacts required for the selected UAT execution.

---

# Owns

RXTA owns:

* remote artifact packaging
* deployment artifact manifests
* artifact transfer
* remote script execution
* deployment workspace management
* deployment logging
* deployment artifact cleanup

---

# Does Not Own

RXTA does not own:

* Relix runtime deployment
* Relix application source code
* Git repository synchronization
* Git repository management on the Relix VM
* Relix runtime lifecycle

---

# Required Architecture

```text
                  Relix Tools VM
┌──────────────────────────────────────────────┐
│ RXTA                                         │
│                                              │
│ relix-deploy                                 │
│ UAT orchestration                            │
│ Deployment packaging                         │
│ Deployment manifest                          │
│ UAT catalogs                                 │
└──────────────────┬───────────────────────────┘
                   │
                   │ Package selected artifacts
                   ▼
           Secure artifact transfer
                   │
                   ▼
              Relix VM
┌──────────────────────────────────────────────┐
│ Relix Runtime                                │
│ Backend services                             │
│ Temporary deployment workspace               │
│ Packaged deployment artifacts                │
│ Remote execution                             │
└──────────────────────────────────────────────┘
```

The complete RXTA repository remains on the Relix Tools VM.

Only packaged deployment artifacts required for the selected execution profile shall be transferred.

---

# Deployment Artifact Model

A deployment artifact is any temporary resource packaged by RXTA for remote execution.

Examples include:

* storage installation scripts
* storage setup scripts
* storage verification scripts
* storage cleanup scripts
* mock database setup scripts
* mock database cleanup scripts
* mock database verification helpers
* mock schema files
* mock seed data
* database migration helpers
* runtime configuration templates
* temporary SQL files
* temporary configuration files

Deployment artifacts are transient and exist only for the duration of the deployment lifecycle.

---

# Mock Database Artifacts

RXTA-owned mock database resources shall be deployed using the same deployment mechanism as all other deployment artifacts.

Mock database artifacts may include:

* mock database setup scripts
* mock schema definitions
* mock seed data
* mock verification helpers
* mock cleanup helpers

Mock database artifacts:

* are deployment artifacts
* shall be packaged by RXTA
* shall be transferred only when required by the selected execution profile
* shall execute from the deployment workspace
* shall be removable through deployment artifact cleanup

Deployment of mock database artifacts does not imply backend eligibility for production UAT.

Mock backend governance and eligibility are defined separately.

---

# Deployment Workspace

Artifacts shall execute from a dedicated temporary deployment workspace.

Example:

```text
/opt/relix-workspace/uat-artifacts
```

The deployment workspace is temporary.

The deployment framework may remove the workspace after deployment completes.

Deployment artifact cleanup is governed by CR-026.

---

# Deployment Requirements

The deployment framework shall:

* package only required deployment artifacts
* generate a deployment manifest
* transfer packaged artifacts to the target environment
* execute artifacts remotely
* report deployment status
* report execution status
* support deterministic deployment
* support repeated deployment where practical
* optionally remove deployment artifacts after execution

The deployment framework shall not:

* synchronize the RXTA repository
* clone the RXTA repository
* require Git on the Relix VM
* execute RXTA directly from the Relix VM

---

# Deployment Manifest

Each deployment shall generate a deployment manifest.

The manifest shall identify:

* deployment identifier
* artifact identifier
* artifact version
* artifact type
* destination path
* execution order (when applicable)
* execution status

The manifest provides deployment traceability without requiring the complete RXTA repository on the target environment.

---

# Deployment Lifecycle

```text
Relix Tools VM

Package deployment artifacts
            ↓
Generate deployment manifest
            ↓
Transfer artifacts
            ↓
Execute remotely
            ↓
Run UAT
            ↓
relix-deploy delete
            ↓
Remove deployment artifacts

Optional

cleanup-storage
            ↓
Reset UAT storage
```

Deployment artifact cleanup removes only temporary deployment artifacts.

Storage cleanup is a separate lifecycle operation governed by CR-026.

Provisioning orchestration is governed by CR-028.

---

# Migration

The following v0.2.1 behaviour is deprecated:

* synchronizing the RXTA repository to the Relix VM
* relying on `/opt/relix-workspace/relix-tools`
* executing RXTA directly from the Relix VM
* `RELIX_VM_TOOLS_HOME`
* `configure_relix_vm_env`
* executing `verify_runtime.py` from the Relix VM

Beginning with v0.2.2:

* RXTA executes only from the Relix Tools VM.
* Only deployment artifacts are transferred.
* Remote execution occurs entirely from packaged deployment artifacts.

---

# Benefits

* clear separation of responsibilities
* reduced deployment footprint
* deterministic deployment
* smaller runtime environment
* improved security
* simplified runtime maintenance
* independent evolution of RXTA and Relix
* reusable deployment mechanism
* identical deployment model for production and mock artifacts

---

# Acceptance Criteria

* No RXTA repository is synchronized or deployed to the Relix VM.
* Only packaged deployment artifacts are transferred.
* Deployment artifacts execute successfully from the deployment workspace.
* Deployment manifests are generated for each deployment.
* Mock database artifacts are deployed as packaged deployment artifacts.
* Mock database deployment does not require the RXTA repository on the Relix VM.
* Production storage deployment uses the same deployment mechanism.
* UAT helper scripts execute remotely without RXTA installed on the Relix VM.
* `relix-deploy delete` removes deployment artifacts without affecting storage resources.
* Temporary deployment artifacts are removable after execution.
* Existing UAT workflows continue to function without repository synchronization.
* Deployment artifact cleanup remains independent of storage cleanup as defined in CR-026.
* Backend provisioning and eligibility remain governed by CR-028.

This version cleanly separates responsibilities:

* **CR-026** — lifecycle script governance.
* **CR-027** — artifact packaging, transfer, execution, and cleanup.
* **CR-028** — provisioning orchestration and backend eligibility.
* **Future Mock DB CR** — mock backend behavior and semantics.

That gives you a coherent, non-overlapping architecture for the deployment subsystem.
