# CR-027 — Remote UAT Artifact Deployment

## Status

Approved for v0.2.2

---

## Objective

Define the deployment model for RXTA UAT artifacts by deploying only the resources required for a specific UAT execution to the Relix VM. The complete RXTA repository shall remain on the Relix Tools VM and shall never be deployed or synchronized to the Relix VM.

---

## Motivation

The Relix VM is a runtime environment responsible for hosting the Relix application and its supporting services.

RXTA is an orchestration and validation framework executed from the Relix Tools VM.

Previous deployment approaches copied portions of the RXTA repository to the Relix VM to execute storage setup scripts and other UAT helpers. This unnecessarily coupled the runtime environment with the validation framework.

The runtime VM should receive only the artifacts required to prepare and execute the selected UAT workload.

---

## Owns

* remote UAT artifact packaging
* artifact deployment
* remote script execution
* deployment workspace management
* deployment manifest generation
* deployment artifact cleanup

---

## Does Not Own

* Relix runtime deployment
* Relix application source code
* RXTA source synchronization
* Git repository management on the Relix VM

---

## Required Architecture

```text
                 Relix Tools VM
        +--------------------------------+
        | RXTA                           |
        |                                |
        | relix-deploy                   |
        | UAT catalogs                   |
        | UAT orchestration              |
        | artifact packaging             |
        +---------------+----------------+
                        |
                        |
              Deploy selected artifacts
                        |
                        v
             +-----------------------------+
             | Relix VM                    |
             |                             |
             | Relix runtime               |
             | PostgreSQL                  |
             | Temporary deployment        |
             | workspace                   |
             | Executed UAT artifacts      |
             +-----------------------------+
```

The complete RXTA repository shall remain on the Relix Tools VM.

Only the deployment artifacts required for the selected execution shall be transferred to the Relix VM.

---

## Deployment Model

Examples of deployable artifacts include:

* storage installation scripts
* storage setup scripts
* storage cleanup scripts
* mock database setup scripts
* mock data files
* database migration helpers
* runtime configuration templates
* temporary SQL files

Artifacts shall be deployed into a dedicated temporary deployment workspace, for example:

```text
/opt/relix-workspace/uat-artifacts
```

Artifacts are executed from this workspace and may be removed after execution.

Deployment artifact removal is governed by **CR-026**.

---

## Requirements

The deployment framework shall:

* package only the artifacts required for the selected execution profile
* transfer only packaged artifacts to the Relix VM
* execute artifacts remotely
* report deployment and execution status
* support idempotent execution where practical
* optionally remove temporary deployment artifacts after execution

The deployment framework shall not:

* synchronize the RXTA repository
* clone the RXTA repository
* require Git on the Relix VM for RXTA
* execute RXTA directly from the Relix VM

---

## Deployment Lifecycle

```text
Relix Tools VM

Package artifacts
        ↓
Transfer artifacts
        ↓
Execute remotely
        ↓
Run UAT
        ↓
relix-deploy delete
        ↓
Remove deployment artifacts

Optional

cleanup-storage
        ↓
Reset UAT storage
```

Deployment artifact cleanup removes only temporary deployment artifacts from the Relix VM.

Storage cleanup is a separate lifecycle operation defined by **CR-026**.

---

## Migration

The following v0.2.1 behavior is deprecated:

* synchronizing the RXTA repository to the Relix VM
* relying on `/opt/relix-workspace/relix-tools`
* executing RXTA directly from the Relix VM
* `RELIX_VM_TOOLS_HOME`
* `configure_relix_vm_env`
* execution of `verify_runtime.py` from the Relix VM

Beginning with v0.2.2, RXTA shall execute from the Relix Tools VM and deploy only the artifacts required for the selected UAT execution.

---

## Benefits

* clear separation of responsibilities
* smaller deployment footprint
* reduced runtime dependencies
* improved security
* deterministic deployment
* simpler runtime environment
* independent evolution of RXTA and Relix
* reusable deployment mechanism for future UAT artifacts

---

## Acceptance Criteria

* No RXTA repository is deployed or synchronized to the Relix VM.
* Only packaged deployment artifacts are transferred to the Relix VM.
* Artifacts execute successfully from the deployment workspace.
* Mock database deployment succeeds using packaged artifacts only.
* Production storage deployment uses the same deployment mechanism.
* UAT helper scripts execute remotely without requiring RXTA on the Relix VM.
* `relix-deploy delete` removes deployment artifacts from the Relix VM without affecting storage resources.
* Temporary deployment artifacts can be removed after execution.
* Existing UAT workflows continue to function without repository synchronization.
