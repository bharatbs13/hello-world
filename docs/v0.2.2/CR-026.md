# CR-026 — RXTA-Owned UAT Environment Script Governance

## Status

Approved for v0.2.2

## Objective

Establish RXTA (`relix-tool`) as the owner of all UAT environment setup and teardown scripts, keeping the Relix runtime repository focused solely on product code. UAT infrastructure, deployment utilities, and environment lifecycle remain governed by RXTA.

---

## Scope

RXTA owns the following UAT environment scripts located under:

```text
relix-tool/
└── automation/
    └── deploy/
        └── scripts/
            ├── install_storage.sh
            ├── setup_uat_storage.sh
            └── cleanup_storage.sh
```

These scripts provision, initialize, and optionally clean UAT storage environments.

---

## Required Architecture

```text
relix-tool (RXTA)
├── owns UAT environment scripts
├── deploys scripts to relix-vm
├── executes install/setup/cleanup during UAT
└── removes deployed artifacts when requested

                │
                ▼

relix-vm
├── temporary UAT deployment artifacts
├── UAT databases
└── execution workspace

                ▲
                │

relix.git
├── runtime/product code only
└── no ownership of UAT infrastructure scripts
```

---

## Ownership Rules

RXTA owns:

* UAT environment scripts
* deployment of scripts to target environments
* execution of install/setup/cleanup operations
* deployment logging
* lifecycle management of deployed UAT artifacts

Relix runtime owns:

* product runtime
* application logic
* migrations
* storage access
* runtime configuration

Relix runtime shall not depend on RXTA UAT scripts.

---

## Script Requirements

Scripts shall:

* be versioned with RXTA
* be safe for repeated execution where practical
* support backend selection
* report unsupported backends as `SKIPPED`
* produce deterministic execution logs
* return non-zero exit codes only for genuine failures

---

## Deployment Lifecycle

### Deploy

`relix-deploy` may copy UAT scripts to the target Relix VM and execute:

* installation
* environment setup
* cleanup, only when explicitly requested

Deployment logs shall record:

* deployed script version
* backend
* execution status
* execution result

---

### Delete

`relix-deploy delete` removes only RXTA deployment artifacts.

Deployment artifacts include only files copied to the Relix VM during deployment.

The canonical copies remain under the RXTA repository.

Examples of removable deployment artifacts include:

* deployed UAT scripts
* temporary deployment files
* temporary execution directories

Typical target locations include:

```text
/opt/relix-workspace/uat-artifacts
/tmp/relix-uat-*
```

Database objects are **not** removed by default.

---

### Storage Cleanup

Storage cleanup is an explicit operation.

Examples:

```bash
relix-deploy cleanup-storage --backend postgres
```

or:

```bash
relix-deploy delete --cleanup-storage
```

Storage cleanup may:

* drop UAT databases
* remove test users
* remove test schemas
* reset storage state

This operation shall be auditable and require explicit invocation.

---

## UAT Lifecycle

```text
Deploy
    ↓
Install storage
    ↓
Setup storage
    ↓
Run UAT
    ↓
Delete deployment artifacts

Optional:
    ↓
Cleanup storage
```

---

## Acceptance Criteria

* UAT environment scripts exist under `relix-tool/automation/deploy/scripts`.
* `relix-deploy` can deploy and execute the scripts on `relix-vm`.
* `relix.git` contains no UAT infrastructure scripts.
* Repeated setup execution is safe.
* Unsupported backends report `SKIPPED`.
* Deployment logs capture execution status.
* `relix-deploy delete` removes only deployment artifacts from the Relix VM by default.
* Canonical script copies remain under the RXTA repository.
* Storage cleanup requires explicit user action.
* Deployment artifact cleanup and storage cleanup are independently executable and auditable.
