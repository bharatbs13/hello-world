# CR-030 — Version-Neutral UAT Test IDs with Composite Internal Keys

## Status

Approved for inclusion in RXTA v0.2.2

## Type

Core Requirement (Catalog Governance Enhancement)

---

# 1. Objective

Introduce version-neutral UAT test identifiers while preserving deterministic cross-version uniqueness through composite internal identity.

The framework shall separate:

- Human-facing test identity
- Version ownership metadata
- Internal catalog uniqueness

This removes redundant version encoding from test IDs while preserving:

- Regression traceability
- Historical compatibility
- Reporting accuracy

---

# 2. Problem Statement

Current RXTA UAT test IDs encode the version directly.

Example:

```text
UAT-V021-FUNC-ADAPTER-001
````

However, version ownership is already represented by catalog metadata:

```yaml
introduced_in: v0.2.1
```

and by version-scoped catalogs:

```text
automation/uat/v0_2_1/catalogs/
```

The version segment therefore duplicates information already owned by the catalog system.

As RXTA grows, this creates:

1. Increasing catalog noise
2. Version-coupled regression references
3. Duplicate logical test identifiers
4. Difficult long-term catalog governance

---

# 3. Scope

## In Scope

* UAT test case identity model
* Catalog loader indexing
* Regression references
* Test lookup APIs
* Reporting metadata
* Backward compatibility with existing versioned IDs

## Out of Scope

* Test execution logic changes
* Test behavior changes
* Coverage selection changes
* Topology scheduling
* Validation semantics

---

# 4. New Test Identity Model

## 4.1 Public Test ID

Version information shall be removed from the public test ID.

### Before

```text
UAT-V021-FUNC-ADAPTER-001
```

### After

```text
UAT-FUNC-ADAPTER-001
```

The public ID represents:

```text
<framework>-<category>-<capability>-<sequence>
```

It does not encode release ownership.

---

# 5. Version Ownership

Version ownership remains defined by catalog metadata.

Example:

```yaml
test_id: UAT-FUNC-ADAPTER-001
introduced_in: v0.2.2
```

`introduced_in` becomes the authoritative source for test origin.

---

# 6. Internal Composite Identity

Catalog storage shall use a composite internal key.

Format:

```text
<introduced_in>::<test_id>
```

Example:

```text
v0.2.2::UAT-FUNC-ADAPTER-001
```

This guarantees uniqueness while keeping user-visible IDs clean.

---

# 7. Catalog Loader Changes

## Current Model

```python
_test_cases[test_id] = test_case
```

## New Model

```python
_test_cases[f"{introduced_in}::{test_id}"] = test_case
```

The `CatalogTestCase.test_id` field remains version-neutral.

---

# 8. Lookup API Changes

The catalog API shall support version-aware lookup.

Example:

```python
get_test_case(
    test_id="UAT-FUNC-ADAPTER-001",
    version="v0.2.2"
)
```

Internally resolves:

```text
v0.2.2::UAT-FUNC-ADAPTER-001
```

If version is omitted and multiple matches exist:

* Do not guess
* Fail with ambiguity error

Example:

```text
Multiple versions found:

- v0.2.1::UAT-FUNC-ADAPTER-001
- v0.2.2::UAT-FUNC-ADAPTER-001

Specify version.
```

---

# 9. Regression Compatibility

Regression references shall use version-neutral IDs.

Example:

```yaml
regression_tests:
  - test_id: UAT-FUNC-ADAPTER-001
    introduced_in: v0.2.1
```

The pair:

```text
introduced_in + test_id
```

forms the regression identity.

---

# 10. Reporting Changes

Reports shall display short IDs while preserving origin metadata.

Example:

```json
{
  "test_id": "UAT-FUNC-ADAPTER-001",
  "introduced_in": "v0.2.2",
  "status": "PASS"
}
```

Reports must not rely on parsing version information from test IDs.

---

# 11. Backward Compatibility

RXTA v0.2.2 shall support both legacy and new formats.

## Legacy Format

```text
UAT-V021-FUNC-ADAPTER-001
```

## New Format

```text
UAT-FUNC-ADAPTER-001
```

Loader behavior:

1. Detect legacy version segment
2. Preserve compatibility
3. Normalize internally into composite identity

---

# 12. Migration Strategy

## v0.2.1

Existing behavior:

```text
UAT-V021-FUNC-ADAPTER-001
```

No changes.

---

## v0.2.2

Introduce:

```text
UAT-FUNC-ADAPTER-001
```

Internal identity:

```text
v0.2.2::UAT-FUNC-ADAPTER-001
```

Support both old and new IDs.

---

## Future Versions

All new tests use version-neutral IDs.

Version ownership remains exclusively through metadata.

# 15. Final Notes

This CR aligns UAT identity management with RXTA catalog governance principles.

A test ID identifies behavior.

A version identifies ownership.

A composite internal key provides uniqueness.

This separation allows RXTA catalogs and regression suites to scale across many releases without accumulating version-specific naming debt.
