# CR-018 — IV Feature Adoption Framework

## Glossary 

`IV` : `Implemented Version`
`PV` : `Proposed Version`



## Target Version

v0.2.1

## Status

Draft

## Objective

Provide automated promotion of accepted Implemented Version (IV) validation coverage into Proposed Version (PV) regression coverage through catalog transformation. The framework discovers the latest accepted IV, identifies eligible feature validation coverage, generates regression coverage for the target PV, and maintains version-to-version validation inheritance without requiring manual regression catalog construction.

## Scope

### Owns

- IV discovery
- last IV determination
- feature adoption eligibility determination
- PV regression generation
- regression catalog generation
- catalog version inheritance
- regression suite generation
- adoption traceability

### Does Not Own

- benchmark planning
- execution identity generation
- suite selection
- topology planning

- diagnostic analysis
- feature validation execution
- regression execution
- version release approval

## Inputs

- feature catalog
- version catalog
- target PV version
- adoption configuration

## Outputs

- regression catalog
- regression suite definitions
- adoption mappings
- version inheritance metadata

## Requirements

### R1.

RXTA shall support IV discovery.

### R2.

RXTA shall determine the latest accepted IV.

### R3.

RXTA shall support generation of regression coverage for a target PV.

### R4.

Regression coverage shall be generated from accepted IV feature coverage.

### R5.

Feature adoption shall be catalog-driven.

### R6.

Version inheritance shall be catalog-driven.

### R7.

RXTA shall generate a regression catalog.

### R8.

RXTA shall generate regression suite definitions.

### R9.

Regression catalog generation shall be deterministic for identical inputs.

### R10.

Identical inputs shall produce identical regression catalogs.

### R11.

The latest accepted IV shall be discoverable from the version catalog.

### R12.

Only accepted IV versions shall be eligible for adoption.

### R13.

Unaccepted IV versions shall not participate in regression generation.

### R14.

Regression coverage shall preserve source feature traceability.

### R15.

Regression entries shall be traceable to originating IV feature coverage.

### R16.

Regression generation shall support version inheritance chains.

### R17.

Catalog inheritance shall not require manual duplication of feature coverage.

### R18.

Regression catalog generation shall be independent of execution planning.

### R19.

Regression catalog generation shall be independent of execution identity generation.

### R20.

Regression catalog generation shall be independent of report aggregation.

### R21.

Generated regression catalogs shall be consumable by CR-012.

### R22.

Generated regression suite definitions shall be consumable by CR-020.

### R23.

Feature adoption shall support incremental version evolution.

### R24.

Feature adoption shall remain valid when no new feature coverage is introduced in the target PV.

### R25.

Version inheritance metadata shall identify the source IV and target PV.

### R26.

Latest accepted IV determination shall be based on version status metadata.

### R27.

Only versions with status ACCEPTED shall be eligible adoption sources.

### R28.

Feature adoption eligibility shall be configuration-driven.

### R29.

When no adoption filter is specified, all accepted IV feature coverage shall be adopted.

## Architecture Notes

### Version Status Model

Version status values:

```text
PROPOSED
IN_PROGRESS
REJECTED
ACCEPTED
SUPERSEDED
```

Latest accepted IV discovery shall consider only:

```text
ACCEPTED
```

versions.

### Adoption Model

```text
Accepted IV
        ↓
Feature Catalog
        ↓
Feature Adoption
        ↓
Regression Catalog
        ↓
PV Regression Coverage
```

### Version Relationship

Example:

```text
IV = v0.2.0
PV = v0.2.1
```

Result:

```text
v0.2.0 accepted features
        ↓
adopted into
        ↓
v0.2.1 regression coverage
```

### Last IV Discovery Model

```text
Version Catalog
        ↓
Version Status
        ↓
ACCEPTED Versions
        ↓
Latest Accepted IV
        ↓
Adoption Source
```

### Adoption Eligibility Model

Default behavior:

```text
Accepted IV Features
        ↓
Adopt All
        ↓
PV Regression Coverage
```

Optional behavior:

```text
Accepted IV Features
        ↓
Adoption Filter
        ↓
Selected Features
        ↓
PV Regression Coverage
```

Adoption eligibility is configuration-driven.

### Catalog Inheritance Model

```text
Feature Catalog
        ↓
Inheritance Rules
        ↓
Regression Catalog
```

Catalog inheritance eliminates manual recreation of regression coverage.

### Adoption Traceability

Each regression entry shall be traceable to:

```text
source_version
source_feature
target_version
adoption_id
```

### Relationship to CR-012

```text
CR-018
    ↓
Regression Catalog

CR-012
    ↓
Regression Planning
```

CR-018 generates regression catalogs.

CR-012 consumes regression catalogs.

### Relationship to CR-020

```text
CR-018
    ↓
Regression Suite Definitions

CR-020
    ↓
Suite Selection
```

CR-018 generates regression suite definitions.

CR-020 consumes regression suite definitions.

### Adoption Rule

```text
Accepted IV Feature
        ↓
Adopt
        ↓
PV Regression Coverage
```

Default rule:

```text
Adopt All Accepted IV Features
```

Optional rule:

```text
Adopt Filtered Accepted IV Features
```

Rejected, incomplete, proposed, or superseded versions are not eligible adoption sources.

### Version Inheritance Metadata

Examples:

```text
source_version
target_version
adoption_status
inheritance_chain
```

## Future Compatibility

The framework shall support future version inheritance models without redesign.

Examples include:

- multi-version inheritance
- long-term support inheritance
- selective feature adoption
- domain-specific inheritance
- solution-specific inheritance

Future catalog structures shall remain metadata-driven.
