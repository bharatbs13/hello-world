# CR-018 — Regression Inheritance Governance Framework

## Target Version

v0.2.1

## Status

**APPROVED** | Architecture-Frozen Baseline v0.2.1

## Objective

Provide regression eligibility and inheritance governance for RXTA. The framework governs which historical validation coverage participates in regression, validates regression inheritance configuration, manages solution-aware regression enablement, supports validation-type-driven regression participation, and enforces pattern-based regression inclusion and exclusion rules without generating regression catalogs or executing regression validation.

## Architecture Notes

### Regression Governance Model

```text
Historical Version
        ↓
status = ACCEPTED
        ↓
regression.yml validation
        ↓
solution enabled?
        ↓
include patterns
        ↓
exclude patterns
        ↓
regression participation
```

Regression Participation Precedence

```text
version eligibility
        ↓
solution enablement
        ↓
include matching
        ↓
exclude matching
        ↓
regression participation
```

Exclude rules override include rules. Disabled solutions override include rules.

Validation-Type Governance

```text
validation_type = current
        ↓
PV coverage only

validation_type = regression
        ↓
eligible regression sources

validation_type = all
        ↓
PV coverage + eligible regression sources
```

Regression Source Eligibility

A historical version is eligible for regression participation when:

1. Version status is ACCEPTED
2. Regression.yml enables the version as a regression source

Versions that are ACCEPTED but not enabled in regression.yml shall not participate.

Regression.yml Configuration

```yaml
regression_for:
  mode: all_future
  from: v0.2.2   # inclusive
  until: v0.3.0  # exclusive; optional

solutions:
  core_runtime:
    enabled: true
  migration:
    enabled: false

include:
  - "*"

exclude:
  - test_id: UAT-V021-FUNC-001
    reason: "superseded by UAT-V022-FUNC-001"
```

from/until semantics:

· from is inclusive — the owning version participates in regression starting from the specified version
· until is exclusive — the owning version stops participating at the specified version
· until omitted means no upper cap — the owning version participates indefinitely

Pattern-Based Governance

Include patterns:

```yaml
include:
  - "*"                          # wildcard all
  - "UAT-V021-FUNC-*"            # wildcard by version
```

Exclude patterns:

```yaml
exclude:
  - test_id: "UAT-V021-FUNC-005"  # exact exclusion
  - test_id: "UAT-V021-*"         # wildcard exclusion by version
```

Exclusion reasons:

```yaml
exclude:
  - test_id: "UAT-V021-FUNC-001"
    reason: "superseded by UAT-V022-FUNC-001"
```

Solution-Aware Governance

Solutions may be enabled or disabled independently:

```yaml
solutions:
  core_runtime:
    enabled: true
  migration:
    enabled: false
```

Disabled solutions are excluded from regression participation regardless of include patterns.

Multi-Version Regression Sources

Regression sources are not limited to a single latest IV.

Example:

```text
PV = v0.2.5
Regression sources = v0.2.0, v0.2.1, v0.2.2, v0.2.3
```

All four versions participate as regression sources when accepted and regression.yml enabled.

Version Status Model

Version status values:

```text
PROPOSED
IN_PROGRESS
REJECTED
ACCEPTED
SUPERSEDED
```

Only ACCEPTED versions are eligible for regression source consideration.

Regression.yml provides an additional governance layer beyond version status.

Adoption Traceability

Each regression participation record shall be traceable to:

```text
source_version
target_version
solution
regression.yml_version
governance_decision
```

Relationship to CR-012

```text
CR-018
    ↓
regression participation metadata

CR-012
    ↓
validation_type driven planning
```

CR-018 determines which historical coverage is eligible for regression participation.

CR-012 determines whether regression coverage is executed based on validation_type selection.

Relationship to CR-020

```text
CR-018
    ↓
regression eligibility records

CR-020
    ↓
suite selection
```

CR-018 determines regression eligibility.

CR-020 consumes eligibility records for suite-based regression selection.

Relationship to CR-025

```text
CR-018
    ↓
regression eligibility

CR-025
    ↓
execution profile eligibility
```

Regression governance determines which historical coverage may participate.

Execution profile governance determines where eligible coverage may execute.

The two governance models are independent.

Governance vs Generation

CR-018 governs regression inheritance. It does not generate regression catalogs.

CR-018 validates regression.yml. It does not generate regression suite definitions.

Regression catalogs and suite definitions are managed through the catalog and suite systems consumed by CR-012 and CR-020.

Future Compatibility

The framework shall support future regression governance models without redesign.

Examples include:

· multi-version inheritance chains
· long-term support regression sources
· domain-specific regression governance
· solution-specific regression governance
· time-windowed regression sources
· selective feature-level governance

Future regression governance shall remain configuration-driven through regression.yml.
