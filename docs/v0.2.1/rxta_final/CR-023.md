
# CR-023 — Solution Benchmark Adapter Framework

## Status
**Draft — Revision 2** | Architecture-Frozen Baseline v0.2.1

## Objective
Provide solution-extensible benchmark execution through adapter registration.

## Owns
- solution adapter contracts
- adapter registration
- adapter discovery
- adapter resolution

## Does Not Own
- benchmark planning (CR-013)
- benchmark configuration (CR-021)
- runtime orchestration (CR-022)

## Key Requirements

| ID | Requirement | Rule |
|----|-------------|------|
| R1 | Registration model | New solutions shall be added through adapter registration |
| R2 | Planning isolation | Addition of a new solution shall not require modification of benchmark planning logic |
| R3 | Runtime isolation | Addition of a new solution shall not require modification of benchmark runtime orchestration logic |
| R4 | Contract conformance | All solution adapters shall implement the abstract benchmark adapter contract |
| R5 | Discovery mechanism | Adapter registry shall support configuration-driven discovery of registered adapters |
| R6 | Resolution determinism | Adapter resolution shall be deterministic based on solution identifier |
| R7 | Graceful absence | Requests for solutions without a registered adapter shall produce a clear, actionable error |

## Abstract Adapter Contract

```

AbstractBenchmarkAdapter
├── solution_identifier: str        (e.g., "core_runtime")
├── supported_types: List[str]      (e.g., ["load", "performance"])
├── validate_config(config) → bool
├── setup(execution_context) → None
├── create_runner(execution_context) → BenchmarkRunner
├── teardown(execution_context) → None
└── metadata() → AdapterMetadata

```

| Method | Purpose |
|--------|---------|
| `validate_config` | Verify configuration is valid for this solution |
| `setup` | Prepare environment before execution |
| `create_runner` | Return a solution-specific runner invoked by CR-022 runtime |
| `teardown` | Clean up after execution |
| `metadata` | Return adapter identity and capabilities |

**Execution boundary:** CR-023 defines the adapter contract and provides the runner. CR-022 runtime invokes the runner and owns the execution lifecycle. CR-023 does not orchestrate execution.

## Registration Model

```yaml
# benchmark_adapters/registry.yaml
adapters:
  - solution: core_runtime
    class: CoreRuntimeBenchmarkAdapter
    path: solutions.core_runtime.adapter
```

Resolution Flow

```
Benchmark execution plan (from CR-013)
    ↓
Extract solution identifier
    ↓
Query adapter registry (CR-023)
    ├── Adapter found → Instantiate → Return runner to CR-022
    └── Adapter not found → Error (actionable message)
```

Explicitly Forbidden

· Solution-specific branching inside benchmark planning (CR-013)
· Solution-specific branching inside runtime orchestration (CR-022)
· Solution-specific branching inside adapter registry resolution (CR-023)
· Hardcoded adapter paths outside the registry
· Runtime modification of adapter registry during execution

Permitted: Solution-specific logic inside the registered solution adapter itself.

Outputs

· resolved adapter — instantiated solution adapter for the benchmark case
· adapter resolution metadata:
  ```
  adapter resolution metadata:
    solution:           core_runtime
    adapter_class:      CoreRuntimeBenchmarkAdapter
    adapter_path:       solutions.core_runtime.adapter
    supported_types:    [load, performance]
    resolution_status:  RESOLVED
    resolution_time_ms: 3
  ```

Acceptance Criteria

ID Criteria
AC1 Adding a new solution adapter requires only registration, no code changes to planning or runtime
AC2 All registered adapters are discoverable via configuration-driven registry
AC3 Resolution is deterministic: same solution always resolves to same adapter
AC4 Unregistered solution request produces actionable error with solution identifier
AC5 Adapter contract violation is caught at registration time, not execution time
AC6 Registry supports multiple solution adapters without conflict
AC7 CR-022 runtime owns execution; CR-023 provides the runner contract
