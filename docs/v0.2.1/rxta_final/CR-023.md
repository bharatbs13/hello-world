# CR-023 — Benchmark Adapter Framework

## Status
**Approved** | Architecture-Frozen Baseline v0.2.1

## Inherited From
CR-022 Benchmark Runtime Framework
CR-013 Benchmark Matrix

## Objective
Provide benchmark-extensible execution through adapter registration supporting solution and benchmark model combinations.

## Owns
- benchmark adapter contracts
- adapter registration
- adapter registration validation
- adapter discovery
- adapter resolution

## Does Not Own
- benchmark planning (CR-013)
- benchmark configuration (CR-021)
- runtime orchestration (CR-022)
- execution lifecycle (CR-022)
- execution profile governance (CR-025)
- aggregation (CR-015)
- reporting (CR-015)

## Inputs
- benchmark execution plan
- solution identifier
- benchmark model identifier
- adapter registry configuration
- execution context

## Key Requirements

| ID | Requirement | Rule |
|----|-------------|------|
| R1 | Registration model | New benchmark adapters shall be added through adapter registration |
| R2 | Planning isolation | Addition of a new adapter shall not require modification of benchmark planning logic |
| R3 | Runtime isolation | Addition of a new adapter shall not require modification of benchmark runtime orchestration logic |
| R4 | Contract conformance | All benchmark adapters shall implement the abstract benchmark adapter contract |
| R5 | Discovery mechanism | Adapter registry shall support configuration-driven discovery of registered adapters |
| R6 | Resolution determinism | Adapter resolution shall be deterministic for identical solution identifier, benchmark model identifier, and registry configuration inputs |
| R7 | Graceful absence | Requests for solution and benchmark model combinations without a registered adapter shall produce a clear, actionable error |
| R8 | Model independence | Multiple benchmark models may exist for the same solution |
| R8a | Registration validation | Adapter registration shall validate contract conformance before the adapter becomes eligible for resolution |

## Abstract Adapter Contract

```

AbstractBenchmarkAdapter
├── solution_identifier: str            (e.g., "core_runtime")
├── benchmark_model_identifier: str     (e.g., "tier_load")
├── supported_types: List[str]          (e.g., ["load", "performance"])
├── validate_config(config) → bool
├── setup(execution_context) → None
├── create_runner(execution_context) → BenchmarkRunner
├── teardown(execution_context) → None
└── metadata() → AdapterMetadata

```

| Method | Purpose |
|--------|---------|
| `validate_config` | Verify configuration is valid for this solution and model |
| `setup` | Prepare environment before execution |
| `create_runner` | Return a benchmark-specific runner invoked by CR-022 runtime |
| `teardown` | Clean up after execution |
| `metadata` | Return adapter identity and capabilities |

**Execution boundary:** CR-023 defines the adapter contract and provides the runner. CR-022 runtime invokes the runner and owns the execution lifecycle. CR-023 does not orchestrate execution.

Resolution Flow

```
Benchmark execution plan (from CR-013)
    ↓
Extract solution identifier
    ↓
Extract benchmark model identifier
    ↓
Query adapter registry (solution, benchmark_model)
    ├── Adapter found → Validate registration → Instantiate → Return runner to CR-022
    └── Adapter not found → Error (actionable message)
```

Explicitly Forbidden

· Solution-specific branching inside benchmark planning (CR-013)
· Solution-specific branching inside runtime orchestration (CR-022)
· Solution-specific branching inside adapter registry resolution (CR-023)
· Benchmark-model-specific branching inside runtime orchestration (CR-022)
· Benchmark-model-specific branching inside adapter registry resolution (CR-023)
· Execution-profile-specific branching inside adapter registry resolution (CR-023)
· Hardcoded adapter paths outside the registry
· Runtime modification of adapter registry during execution

Permitted: Solution-specific logic and benchmark-model-specific logic inside the registered benchmark adapter itself.

Outputs

· resolved adapter — instantiated benchmark adapter for the benchmark case
· adapter resolution metadata:
  ```
  adapter resolution metadata:
    solution:               core_runtime
    benchmark_model:        tier_load
    adapter_class:          CoreRuntimeTierLoadAdapter
    adapter_path:           adapters.core_runtime.tier_load_adapter
    supported_types:        [load, performance]
    resolution_status:      RESOLVED
    resolution_time_ms:     3
  ```

Acceptance Criteria

ID Criteria
AC1 Adding a new benchmark adapter requires only registration, no code changes to planning or runtime
AC2 All registered adapters are discoverable via configuration-driven registry
AC3 Resolution is deterministic: same solution, benchmark model, and registry configuration always resolves to same adapter
AC4 Unregistered solution and model combination produces actionable error with both identifiers
AC5 Adapter contract violation is caught at registration time, not execution time
AC6 Registry supports multiple benchmark adapters without conflict
AC7 CR-022 runtime owns execution; CR-023 provides the runner contract
AC8 Multiple benchmark models may exist for the same solution
AC9 Adapter resolution consumes solution identifier and benchmark model identifier
