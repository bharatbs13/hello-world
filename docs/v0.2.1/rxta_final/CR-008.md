# CR-008 — Pytest Report Integration

## Target Version

v0.2.1

## Status

Draft Final

## Objective

Integrate pytest execution outputs into RXTA validation reporting. The framework consumes pytest-generated execution artifacts, transforms them into RXTA-compatible execution results, and provides standardized reporting inputs for aggregation, diagnostics, and validation traceability.

## Scope

### Owns

* pytest report discovery
* pytest report ingestion
* pytest report transformation
* pytest result normalization
* pytest-to-RXTA result mapping
* pytest report traceability

### Does Not Own

* test execution
* execution identity generation
* validation planning
* report aggregation
* diagnostic analysis
* deployment
* infrastructure selection

## Inputs

* pytest execution reports
* pytest result artifacts
* execution metadata
* report integration configuration

## Outputs

* normalized execution results
* pytest mapping metadata
* pytest traceability metadata
* RXTA-compatible execution result records

## Requirements

### R1.

RXTA shall support pytest report ingestion.

### R2.

RXTA shall support pytest execution artifact discovery.

### R3.

RXTA shall support transformation of pytest results into RXTA-compatible execution results.

### R4.

Pytest report integration shall be configuration-driven.

### R5.

Pytest result normalization shall be deterministic.

### R6.

Identical pytest artifacts shall produce identical normalized execution results.

### R7.

Pytest execution outcomes shall be mapped into RXTA execution outcomes.

### R8.

Pytest report integration shall preserve execution traceability.

### R9.

Pytest report integration shall preserve test-case traceability.

### R10.

Pytest report integration shall not modify original pytest artifacts.

### R11.

Normalized execution results shall be consumable by CR-015 aggregation.

### R12.

Normalized execution results shall be consumable by CR-017 diagnostics.

### R13.

Pytest integration shall support partial result ingestion.

### R14.

Pytest integration shall identify malformed report artifacts.

### R15.

Pytest integration shall identify unsupported report formats.

### R16.

Pytest integration shall report ingestion anomalies.

### R17.

Pytest integration shall support execution_id association when execution metadata is available.

### R18.

Pytest integration shall remain valid when optional execution dimensions are absent.

### R19.

Pytest integration shall be independent of execution planning.

### R20.

Pytest integration shall be independent of runtime execution.

### R21.

CR-008 shall support pytest JUnit XML ingestion.

### R22.

JUnit XML shall be the required pytest report format for v0.2.1.

### R23.

CR-008 shall define deterministic mapping from pytest outcomes to RXTA execution outcomes.

## Architecture Notes

### Supported Report Format (v0.2.1)

```text
pytest
    ↓
JUnit XML
    ↓
CR-008 Ingestion
```

Additional report formats may be supported in future versions.

### Integration Model

```text
Pytest Reports
        ↓
Discovery
        ↓
Ingestion
        ↓
Normalization
        ↓
RXTA Execution Results
```

### Result Mapping Model

```text
Pytest Result
        ↓
Result Mapping
        ↓
RXTA Execution Result
```

### Pytest Outcome Mapping

| Pytest Outcome   | RXTA Outcome      |
| ---------------- | ----------------- |
| passed           | PASSED            |
| failed           | FAILED            |
| error            | FAILED            |
| skipped          | SKIPPED           |
| xfailed          | XFAILED           |
| xpassed          | XPASSED           |
| malformed report | INGESTION_ANOMALY |
| missing report   | INGESTION_ANOMALY |

### Traceability Model

```text
pytest artifact
        ↓
execution metadata
        ↓
execution result
```

### Ingestion Anomaly States

```text
VALID
MALFORMED
MISSING
UNSUPPORTED_FORMAT
PARTIAL
```

### Relationship to CR-015

```text
CR-008
    ↓
Normalized Results

CR-015
    ↓
Aggregation
```

CR-008 provides normalized execution results.

CR-015 performs aggregation.

### Relationship to CR-017

```text
CR-008
    ↓
Normalized Results

CR-017
    ↓
Diagnostics
```

CR-008 provides execution results.

CR-017 performs diagnostic analysis.

### Relationship to CR-016

```text
CR-016
    ↓
Execution Metadata

CR-008
    ↓
Result Association
```

CR-016 owns execution identity.

CR-008 consumes execution metadata when available.

### Preservation Rule

```text
Original Pytest Artifact
        ↓
Read Only
        ↓
Normalized Result
```

Original pytest artifacts shall remain unchanged.

### Outcome Preservation Rule

Normalized RXTA outcomes shall preserve pytest semantic intent.

Examples:

```text
skipped  → SKIPPED
xfailed  → XFAILED
xpassed  → XPASSED
```

These outcomes remain distinct and are not automatically collapsed into PASSED, FAILED, or ABORTED.

## Future Compatibility

The framework shall support future test-report integrations without redesign.

Examples include:

* pytest JUnit XML
* unittest result adapters
* nose result adapters
* custom validation frameworks
* benchmark result frameworks

Future integrations shall remain metadata-driven.

### AC7.

### AC8.

Normalized execution results are consumable by CR-015.
