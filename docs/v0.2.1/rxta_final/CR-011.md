# CR-011 — Command-Aware Prompt Resolution

## Target Version

v0.2.1

## Status

Draft Final

## Objective

Collect only the runtime inputs required for the requested RXTA operation. The framework resolves command-specific input requirements, suppresses unnecessary prompts, and ensures users are only asked for information relevant to the selected command, coverage tier, validation type, execution profile, and configuration context.

## Scope

### Owns

* prompt discovery
* prompt suppression
* command-aware prompt resolution
* runtime input requirement evaluation
* prompt eligibility determination
* prompt traceability
* command-specific prompt rules
* runtime input precedence resolution
* override traceability

### Does Not Own

* deployment
* infrastructure selection
* execution planning
* execution identity generation
* validation execution
* report generation
* runtime execution
* configuration storage

* command definition
* command arguments

* command metadata
* prompt resolution rules

* validation type

## Outputs

* prompt traceability

* runtime_input_set

### R20.

Prompt resolution shall be independent of validation execution.

### R21.

Prompt resolution shall be independent of report generation.

### R22.

Prompt resolution shall support future commands without redesign.

### R23.

Prompt requirements shall be command-specific.

### R24.

Prompt suppression shall occur when required inputs are already satisfied.

### R25.

Prompt resolution shall report unresolved required inputs when required inputs cannot be satisfied through configuration, command arguments, environment metadata, or user input.

### R26.

Command execution shall not proceed when unresolved required inputs exist.

### R27.

Runtime input resolution shall apply a deterministic precedence order when the same input is available from multiple sources.

### R28.

Prompt resolution metadata may record overridden runtime input values when a higher-precedence source replaces a lower-precedence source.

## Architecture Notes

### Command-Aware Resolution Model

```text
Command
        ↓
Input Requirement Evaluation
        ↓
Prompt Discovery
        ↓
Prompt Suppression
        ↓
Resolved Runtime Inputs
```

Runtime Input Precedence

When the same input is available from multiple sources, resolution shall apply the following precedence order:

```text
command arguments       (highest)
        ↓
user input
        ↓
environment metadata
        ↓
configuration           (lowest)
```

Higher-precedence sources override lower-precedence sources for the same input.

Override Traceability

When a higher-precedence source overrides a lower-precedence source, resolution metadata may record:

```text
override_record:
    input: execution_profile
    selected_value: real_db
    selected_source: cli
    overridden_value: mock_db
    overridden_source: config
```

Prompt Decision Model

```text
Required Input
        ↓
Available?
        ↓
Yes → Suppress Prompt

No  → Prompt User
```

Runtime Input Sources

Runtime inputs may originate from:

```text
command arguments
configuration
user input
environment metadata
```

Prompt resolution shall prefer existing inputs before requesting new inputs.

Runtime Input Set

```text
{
  "command": "test",
  "inputs": {
    "coverage_tier": "full",
    "validation_type": "current",
    "execution_profile": "real_db"
  },
  "resolution_sources": {
    "coverage_tier": "cli",
    "validation_type": "default",
    "execution_profile": "config"
  }
}
```

CLI Alias Mapping

```text
full → feature
```

CLI aliases may be mapped to internal catalog values during prompt resolution.

Execution Profile Expansion

```text
mock_db
    ↓
no_db + mock_db

real_db
    ↓
real_db

all_db
    ↓
no_db + mock_db + real_db
```

Execution profile expansion rules are applied deterministically during prompt resolution.

Test Command Example

```text
Command:
    test

Possible Inputs:
    coverage_tier
    validation_type
    execution_profile
    topology

Not Required:
    git credentials
```

Result:

```text
git credential prompt suppressed
```

Deploy Command Example

```text
Command:
    deploy

Deployment Source:
    git_tag
```

Possible Inputs:

```text
repository access
git credentials
deployment target
```

Result:

```text
git credential prompt allowed
```

Prompt Suppression Model

```text
Input Available
        ↓
Prompt Suppressed
```

Examples:

```text
coverage_tier supplied
        ↓
coverage_tier prompt suppressed

execution_profile supplied
        ↓
execution_profile prompt suppressed
```

Unresolved Input Model

```text
Required Input
        ↓
Unavailable
        ↓
Unresolved Input
        ↓
Execution Blocked
```

Prompt Traceability

Prompt records shall contain:

```text
command
required_input
prompt_status
resolution_source
```
