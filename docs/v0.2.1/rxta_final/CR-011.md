# CR-011 — Command-Aware Prompt Resolution

## Target Version

v0.2.1

## Status

Draft Final

## Objective

Collect only the runtime inputs required for the requested RXTA operation. The framework resolves command-specific input requirements, suppresses unnecessary prompts, and ensures users are only asked for information relevant to the selected command, execution mode, and configuration context.

## Scope

### Owns

* prompt discovery
* prompt suppression
* command-aware prompt resolution
* runtime input requirement evaluation
* prompt eligibility determination
* prompt traceability
* command-specific prompt rules

### Does Not Own

* deployment
* infrastructure selection
* execution planning
* execution identity generation
* validation execution
* report generation
* runtime execution
* configuration storage

## Inputs

* command definition
* command arguments
* runtime configuration
* command metadata
* prompt resolution rules

## Outputs

* resolved runtime inputs
* prompt decisions
* prompt traceability
* prompt resolution metadata
* unresolved required inputs

## Requirements

### R1.

RXTA shall support command-aware prompt resolution.

### R2.

RXTA shall determine required runtime inputs based on the selected command.

### R3.

RXTA shall suppress prompts for inputs not required by the selected command.

### R4.

Prompt resolution shall be rule-driven.

### R5.

Prompt resolution shall be deterministic for identical command inputs.

### R6.

Identical command inputs shall produce identical prompt decisions.

### R7.

RXTA shall support prompt discovery.

### R8.

RXTA shall support prompt suppression.

### R9.

Prompt resolution shall occur before command execution.

### R10.

Prompt resolution shall evaluate command arguments.

### R11.

Prompt resolution shall evaluate available runtime configuration.

### R12.

Prompt resolution shall avoid requesting inputs already available through configuration.

### R13.

Prompt decisions shall be traceable.

### R14.

Prompt resolution metadata shall identify the originating command.

### R15.

Prompt resolution metadata shall identify required runtime inputs.

### R16.

Prompt resolution metadata shall identify suppressed prompts.

### R17.

The test command shall not request Git credentials.

### R18.

The deploy command may request Git credentials when required by the selected deployment source.

### R19.

Prompt resolution shall be independent of deployment execution.

### R20.

Prompt resolution shall be independent of validation execution.

### R21.

Prompt resolution shall be independent of report generation.

### R22.

Prompt resolution shall support future commands without redesign.

### R23.

Prompt requirements shall be command-specific.

### R24.

Prompt suppression shall occur when required inputs are already satisfied.

### R25.

Prompt resolution shall report unresolved required inputs when required inputs cannot be satisfied through configuration, command arguments, environment metadata, or user input.

### R26.

Command execution shall not proceed when unresolved required inputs exist.

## Architecture Notes

### Command-Aware Resolution Model

```text
Command
        ↓
Input Requirement Evaluation
        ↓
Prompt Discovery
        ↓
Prompt Suppression
        ↓
Resolved Runtime Inputs
```

### Prompt Decision Model

```text
Required Input
        ↓
Available?
        ↓
Yes → Suppress Prompt

No  → Prompt User
```

### Runtime Input Sources

Runtime inputs may originate from:

```text
command arguments
configuration
user input
environment metadata
```

Prompt resolution shall prefer existing inputs before requesting new inputs.

### Test Command Example

```text
Command:
    test

Possible Inputs:
    suite
    phase
    topology

Not Required:
    git credentials
```

Result:

```text
git credential prompt suppressed
```

### Deploy Command Example

```text
Command:
    deploy

Deployment Source:
    git_tag
```

Possible Inputs:

```text
repository access
git credentials
deployment target
```

Result:

```text
git credential prompt allowed
```

### Prompt Suppression Model

```text
Input Available
        ↓
Prompt Suppressed
```

Examples:

```text
deployment target supplied
        ↓
deployment target prompt suppressed

suite supplied
        ↓
suite prompt suppressed
```

### Unresolved Input Model

```text
Required Input
        ↓
Unavailable
        ↓
Unresolved Input
        ↓
Execution Blocked
```

### Prompt Traceability

Prompt records shall contain:

```text
command
required_input
prompt_status
resolution_source
```
