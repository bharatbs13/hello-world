# CR-021 — Benchmark Configuration Framework

## Status
**Approved with Minor Revisions** | Architecture-Frozen Baseline v0.2.1+

## Inherited From
CR-013 Benchmark Matrix

## Objective
Provide configuration-driven benchmark enablement, selection, and governance.

## Owns
- benchmark configuration
- solution enablement
- benchmark type enablement
- benchmark profile enablement
- benchmark case enablement
- selection governance

## Does Not Own
- benchmark planning
- benchmark execution
- benchmark runtime
- aggregation
- reporting

## Key Requirements

| ID | Requirement | Rule |
|----|-------------|------|
| R1 | YAML authoritative | Configuration is the source of truth |
| R2 | CLI narrowing | CLI selection may narrow benchmark coverage |
| R3 | CLI restriction | CLI selection shall not enable coverage disabled by configuration |
| R4 | Planning exclusion | Disabled coverage shall not participate in benchmark planning |
| R5 | Deterministic resolution | Identical configuration and CLI inputs shall produce identical effective benchmark selections |
| R6 | Unknown identifier reporting | Selection resolution shall report unknown benchmark identifiers |
| R7 | Unknown identifier exclusion | Unknown benchmark identifiers shall not participate in effective benchmark selection |

## Configuration Hierarchy

```

benchmark.yaml
├── solutions
│   ├── core_runtime (enabled: true/false)
│   ├── migration (enabled: true/false)
│   ├── backup_restore (enabled: true/false)
│   └── disaster_recovery (enabled: true/false)
├── types
│   ├── load (enabled: true/false)
│   └── performance (enabled: true/false)
├── profiles
│   ├── baseline (enabled: true/false)
│   ├── peak (enabled: true/false)
│   └── stress (enabled: true/false)
└── cases
├── BENC-001 (enabled: true/false)
├── BENC-002 (enabled: true/false)
└── ...

```

## Resolution Rules

```

YAML configuration (authoritative)
↓
CLI selection (narrowing only)
↓
effective benchmark selection

```

1. Start with YAML configuration as authoritative.
2. Apply CLI selection as a narrowing filter.
3. Disabled items in YAML remain disabled regardless of CLI input.
4. Unknown identifiers are reported and excluded.
5. Resolution is deterministic: identical inputs produce identical outputs.

## Outputs

- **effective benchmark selection** — final set of enabled benchmark cases

- **benchmark selection metadata:**
    ```
    benchmark selection metadata:
      selected_solutions:    [core_runtime]
      selected_types:        [load, performance]
      selected_profiles:     [baseline, peak]
      selected_cases:        [BENC-001, BENC-002, ...]
      disabled_by_configuration: [migration, stress, BENC-005]
      filtered_by_cli:       [BENC-003]
    ```

## Acceptance Criteria

| ID | Criteria |
|----|----------|
| AC1 | A disabled benchmark case remains disabled when selected through CLI |
| AC2 | CLI narrowing reduces benchmark coverage without expanding coverage |
| AC3 | Identical configuration and CLI inputs produce identical selections |
| AC4 | Unknown benchmark identifiers are reported to the user |
| AC5 | Unknown benchmark identifiers are excluded from the effective selection |
