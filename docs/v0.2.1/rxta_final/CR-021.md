# CR-021 — Benchmark Configuration Framework

## Status
**Approved** | Architecture-Frozen Baseline v0.2.1

## Inherited From
CR-013 Benchmark Matrix

## Objective
Provide configuration-driven benchmark enablement, selection, and governance.

## Owns
- benchmark coverage enablement governance
- benchmark partition enablement configuration
- benchmark solution enablement configuration
- benchmark model enablement
- benchmark type enablement
- benchmark profile enablement
- benchmark case enablement
- selection governance

## Does Not Own
- benchmark planning
- benchmark execution
- benchmark runtime
- aggregation
- reporting
- execution profile governance

## Inputs
- benchmark configuration (benchmark.yaml)
- execution profile selection
- CLI selection arguments
- benchmark catalog metadata

## Key Requirements

| ID | Requirement | Rule |
|----|-------------|------|
| R1 | YAML authoritative | Configuration is the source of truth |
| R2 | CLI narrowing | CLI selection may narrow benchmark coverage |
| R3 | CLI restriction | CLI selection shall not enable coverage disabled by configuration |
| R4 | Planning exclusion | Disabled coverage shall not participate in benchmark planning |
| R5 | Deterministic resolution | Identical configuration and CLI inputs shall produce identical effective benchmark selections |
| R6 | Unknown identifier reporting | Selection resolution shall report unknown benchmark identifiers |
| R7 | Unknown identifier exclusion | Unknown benchmark identifiers shall not participate in effective benchmark selection |
| R8 | Benchmark model metadata | Benchmark configuration shall support benchmark model metadata |
| R9 | Execution profile filtering | Benchmark selection shall support execution profile eligibility filtering |
| R10 | Execution profile independence | Benchmark configuration shall remain independent of execution profile governance rules defined by CR-025 |

## Governance Precedence

```

domain partition enabled?
↓
solution enabled?
↓
benchmark model enabled?
↓
benchmark type enabled?
↓
profile enabled?
↓
case enabled?
↓
effective benchmark selection
↓
execution profile filtering (CR-025)
↓
eligible for planning

```

Each level may independently enable or disable coverage. A disabled item at any level removes all descendant items from the effective selection. Execution profile filtering is applied after benchmark configuration and is owned by CR-025.

## Resolution Rules

```

YAML configuration (authoritative)
↓
CLI selection (narrowing only)
↓
effective benchmark selection
↓
execution profile filtering (CR-025)
↓
eligible for benchmark planning

```

1. Start with YAML configuration as authoritative.
2. Apply governance precedence across domain, solution, model, type, profile, and case levels.
3. Apply CLI selection as a narrowing filter.
4. Disabled items in YAML remain disabled regardless of CLI input.
5. Unknown identifiers are reported and excluded.
6. Resolution is deterministic: identical inputs produce identical outputs.
7. Execution profile filtering is applied by CR-025 after effective benchmark selection.

## CLI Selection Examples

Single dimension narrowing:

```text
rxta benchmark --solution core_runtime
rxta benchmark --type load
rxta benchmark --profile baseline
rxta benchmark --case BENC-001
rxta benchmark --execution-profile real_db
```

Multi-dimension narrowing:

```text
rxta benchmark \
  --solution core_runtime \
  --type load \
  --profile baseline

rxta benchmark \
  --solution core_runtime \
  --profile baseline \
  --execution-profile real_db
```

All eligible:

```text
rxta benchmark --all
```

CLI selection narrows within the boundaries set by YAML configuration. CLI cannot expand coverage beyond what YAML enables.

Outputs

· effective benchmark selection — final set of enabled benchmark cases
· benchmark selection metadata:
  ```
  benchmark selection metadata:
    selected_partitions:   [backend]
    selected_solutions:    [core_runtime]
    selected_models:       [tier_load]
    selected_types:        [load, performance]
    selected_profiles:     [baseline, peak]
    selected_cases:        [BENC-001, BENC-002, ...]
    disabled_by_configuration: [migration, stress, BENC-005]
    filtered_by_cli:       [BENC-003]
    filtered_by_execution_profile: [BENC-004, BENC-007]
  ```

Acceptance Criteria

ID Criteria
AC1 A disabled benchmark case remains disabled when selected through CLI
AC2 CLI narrowing reduces benchmark coverage without expanding coverage
AC3 Identical configuration and CLI inputs produce identical selections
AC4 Unknown benchmark identifiers are reported to the user
AC5 Unknown benchmark identifiers are excluded from the effective selection
AC6 Disabled domain partition excludes all descendant benchmark coverage
AC7 Disabled solution excludes all descendant benchmark coverage
AC8 Benchmark model metadata is consumable by benchmark execution planning
AC9 Execution profile filtering may reduce benchmark coverage
AC10 Execution profile filtering shall not enable coverage disabled by benchmark configuration
AC11 Identical benchmark configuration, execution profile, and CLI inputs produce identical benchmark selections
