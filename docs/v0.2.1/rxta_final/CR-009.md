# CR-009 — Infrastructure Selection Framework

## Target Version

v0.2.1

## Status

**APPROVED** | Architecture-Frozen Baseline v0.2.1

## Objective

Provide controlled infrastructure selection for RXTA execution through inventory-driven infrastructure selection. The framework manages infrastructure inventories, applies infrastructure selection policies, and produces infrastructure selection metadata consumable by execution planning. The framework supports deterministic and non-deterministic selection modes while remaining independent of topology planning, execution planning, validation planning, and reporting.

### R12.

Infrastructure selection shall produce a selected infrastructure set.

### R13.

Infrastructure selection shall produce infrastructure selection metadata.

### R14.

Infrastructure selection shall produce infrastructure selection traceability.

Fixed selection mode shall select infrastructure explicitly identified by configuration.

### R16.

Random selection mode shall select infrastructure from eligible inventory entries.

### R17.

Full_set selection mode shall select all eligible inventory entries.

### R18.

Infrastructure selection shall be deterministic when using fixed selection mode.

### R19.

Infrastructure selection metadata shall identify selected infrastructure entries.

### R20.

Infrastructure selection metadata shall be consumable by execution planning frameworks.

### R21.

Infrastructure selection shall be independent of topology planning.

### R22.

Infrastructure selection shall be independent of execution identity generation.

### R23.

Infrastructure selection shall be independent of report aggregation.

### R24.

Infrastructure selection shall support current infrastructure inventories without requiring topology awareness.

### R25.

Infrastructure selection shall remain compatible with future infrastructure types.

### R26.

Infrastructure selection outputs shall be consumable by CR-014 topology planning.

### R27.

Infrastructure selection outputs shall be consumable by CR-012 functional planning.

### R28.

Infrastructure selection outputs shall be consumable by CR-013 benchmark planning.

### R29.

Random selection mode shall support deterministic selection through a configurable seed.

### R30.

Identical inventory, configuration, eligibility metadata, and seed shall produce identical selections.

### R31.

Infrastructure selection shall fail when no eligible infrastructure entries exist for the requested selection mode.

### R32.

Each infrastructure selection operation shall possess exactly one selection_id.

### R33.

Selection IDs shall be unique within a run.

## Architecture Notes

### Infrastructure Inventory Model

```text
VM Inventory
Database Inventory
Environment Inventory
        ↓
Eligibility Evaluation
        ↓
Eligible Infrastructure
        ↓
Infrastructure Selection
```

Selection Modes

Mode Description
fixed Select explicitly configured infrastructure
random Select infrastructure from eligible inventory
full_set Select all eligible infrastructure

Selection Identity

```text
selection_id
    ↓
selection_mode
    ↓
selected_infrastructure_set
```

Each infrastructure selection operation possesses exactly one selection_id. Selection IDs are unique within a run.

Selection Outcomes

```text
SELECTED
FAILED_NO_ELIGIBLE_INFRASTRUCTURE
```

Outcome Description
SELECTED One or more infrastructure entries selected
FAILED_NO_ELIGIBLE_INFRASTRUCTURE No eligible infrastructure exists for the requested selection mode

Fixed Selection Model

```text
Configured Infrastructure
        ↓
Eligibility Validation
        ↓
Selected Infrastructure
```

Random Selection Model

```text
Eligible Infrastructure
        ↓
Optional Seed
        ↓
Random Selection
        ↓
Selected Infrastructure
```

When a seed is supplied, selection shall be reproducible.

Full Set Selection Model

```text
Eligible Infrastructure
        ↓
Select All
        ↓
Selected Infrastructure Set
```

Selected Infrastructure Metadata

```text
selected_infrastructure:
    infrastructure_type: vm | database | environment
    infrastructure_id:   VM-A | DB-01 | AWS-UAT
    selection_id:        SEL-001
```

Empty Selection Behavior

```text
Eligible Infrastructure = 0
        ↓
Selection Failure
        ↓
Outcome: FAILED_NO_ELIGIBLE_INFRASTRUCTURE
```

Infrastructure selection shall fail when no eligible infrastructure exists for the requested selection mode.

Infrastructure Selection Traceability

Infrastructure selection records shall contain:

```text
selection_id
selection_mode
selected_infrastructure
selection_outcome
selection_status
```

Relationship to CR-014

```text
CR-009
    ↓
Selected Infrastructure Set

CR-014
    ↓
Topology Planning
```

CR-009 selects infrastructure.

CR-014 plans topology roles and topology signatures.

CR-009 does not perform topology planning.

Relationship to CR-012 and CR-013

```text
CR-009
    ↓
Infrastructure Metadata

CR-012
    ↓
Functional Planning

CR-013
    ↓
Benchmark Planning
```

CR-009 provides infrastructure metadata.

CR-012 and CR-013 consume infrastructure metadata.

Infrastructure Ownership Boundary

Examples owned by CR-009:

```text
VM-A
VM-B
AWS-DEV
AWS-UAT
DB-HOST-01
DB-HOST-02
```

Examples not owned by CR-009:

```text
source
target
relay
primary
secondary
```

Infrastructure role ownership belongs to CR-014.

Selection Independence

Infrastructure selection does not require:

```text
topology_id
depth_id
execution_id
suite
```

Infrastructure selection is performed before planning frameworks consume selected infrastructure metadata.

Future Compatibility

The framework shall support future infrastructure types without redesign.

Examples include:

· cloud providers
· VM classes
· container platforms
· database clusters
· managed database services
· hybrid infrastructure environments

Future inventories shall remain metadata-driven.
