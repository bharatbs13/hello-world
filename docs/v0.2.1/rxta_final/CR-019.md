# CR-019 — Mock Connector Alignment Framework

## Target Version

v0.2.1

## Status

Draft Final

## Objective

Maintain architectural compatibility between Phase 1 mock-based validation and Phase 2 real-system validation through alignment governance. The framework maps mock connectors, mock topologies, and mock depth profiles to their Phase 2 equivalents, validates alignment correctness, and ensures that validation coverage developed during Phase 1 remains reusable and representative during Phase 2 execution without duplicating topology or infrastructure ownership.

## Architecture Notes

### Phase Model

```text
Phase 1
    ↓
Mock Connectors
    ↓
Mock Topologies
    ↓
Mock Depth Profiles

Phase 2
    ↓
Real Connectors
    ↓
Real Topologies
    ↓
Real Depth Profiles
```

Alignment Model

```text
Phase 1 Artifact
        ↓
Alignment Mapping (CR-019)
        ↓
Phase 2 Artifact (CR-014)
```

CR-019 owns the mapping between Phase 1 and Phase 2 artifacts. CR-014 owns the artifacts themselves.

Connector Alignment

```text
Mock Connector
        ↓
Alignment Mapping
        ↓
Real Connector
```

Examples:

```text
Mock PostgreSQL
        ↓
PostgreSQL

Mock MySQL
        ↓
MySQL
```

Topology Alignment

```text
Mock Topology
        ↓
Alignment Mapping
        ↓
Phase 2 Topology
```

Examples:

```text
mock_single_db
        ↓
single_db

mock_source_target
        ↓
source_target
```

Topology profiles and mock topology profiles are defined and owned by CR-014. CR-019 maps between them.

Depth Alignment

```text
Mock Depth Profile
        ↓
Alignment Mapping
        ↓
Phase 2 Depth Profile
```

Infrastructure Signature Alignment

Mock infrastructure signatures represent infrastructure role participation only.

Examples:

```text
source
target
relay
primary
secondary
```

Mock infrastructure signatures do not represent actual infrastructure selection.

Infrastructure selection remains outside the scope of CR-019.

Alignment Outcomes

```text
ALIGNED
PARTIALLY_ALIGNED
NOT_ALIGNED
MISSING_MAPPING
```

Outcome Description
ALIGNED All Phase 1 artifacts have valid Phase 2 mappings
PARTIALLY_ALIGNED Some Phase 1 artifacts have valid Phase 2 mappings; others do not
NOT_ALIGNED Phase 1 and Phase 2 definitions are incompatible
MISSING_MAPPING Phase 2 mapping is absent for one or more Phase 1 artifacts

Canonical Mapping Rule

Each Phase 1 artifact shall map to exactly one canonical Phase 2 artifact. Multiple Phase 1 artifacts may map to the same Phase 2 artifact.

```text
Phase 1                     Phase 2

mock_single_db      →       single_db
mock_postgres       →       postgres
mock_mysql          →       mysql
mock_source_a       →       source_target
mock_source_b       →       source_target   (allowed: multiple-to-one)
mock_source_target  →       source_target
```

Alignment Registry

```text
run_id
    ↓
alignment_registry
    ├── alignment_id
    ├── phase1_artifact
    ├── phase2_artifact
    ├── alignment_status
    └── alignment_outcome
```

Each run-scoped alignment registry is associated with exactly one run_id. Registry contents are immutable after alignment validation completes. Registry entries are uniquely identifiable by alignment_id.

Alignment Identity

Each alignment mapping possesses exactly one alignment_id. Alignment IDs are unique within an alignment registry.

Alignment Traceability

Alignment mappings shall be traceable through:

```text
alignment_id
phase1_artifact
phase2_artifact
alignment_status
alignment_outcome
```

Relationship to CR-014

```text
CR-014
    ↓
topology profiles
depth profiles
infra_signatures

CR-019
    ↓
alignment mappings
```

CR-014 owns topology artifacts. CR-019 owns the alignment mappings between Phase 1 and Phase 2 versions of those artifacts. CR-019 does not generate topology profiles, depth profiles, or infrastructure signatures.

Relationship to CR-018

```text
CR-018
    ↓
regression participation metadata

CR-019
    ↓
alignment mappings

CR-012
    ↓
execution planning
```

CR-018 determines which historical coverage participates in regression. CR-019 ensures Phase 1 coverage remains mappable to Phase 2 execution environments. Together they enable regression reuse across phases.

Relationship to CR-012 and CR-013

```text
CR-019
    ↓
Alignment Mappings

CR-012
    ↓
Functional Planning

CR-013
    ↓
Benchmark Planning
```

CR-019 provides compatibility mappings.

CR-012 and CR-013 consume aligned metadata.

Compatibility Rule

```text
Phase 1 Architecture
        ↓
Alignment
        ↓
Phase 2 Architecture
```

Validation coverage developed during Phase 1 shall remain applicable to corresponding Phase 2 architectures through alignment mappings.

Future Compatibility

The framework shall support future alignment models without redesign.

Examples include:

· multi-hop topologies
· migration architectures
· backup and restore architectures
· disaster recovery architectures
· domain-specific connector mappings
· solution-specific connector mappings

Future connector catalogs, topology profiles, and depth profiles shall remain metadata-driven.
