# CR-010 — Automated relix-tools Deployment

## Target Version

v0.2.1

## Status

Draft Final

## Objective

Prepare execution environments automatically through deployment of relix-tools, dependency installation, runtime preparation, and deployment verification. The framework supports multiple deployment source modes, enabling reproducible execution environments for development, testing, and release validation while remaining independent of execution planning, execution identity generation, validation execution, and reporting.

### R7.

### R8.

RXTA shall install required dependencies.

RXTA shall prepare required runtime environments.

### R10.

RXTA shall verify successful deployment.

Deployment verification shall validate dependency installation.

### R13.

Deployment verification shall validate runtime readiness.

### R14.

### R15.

Deployment metadata shall identify deployment target path.

RXTA shall not assume version equivalence between relix and relix-tools.

### R21.

### R22.

Deployment configuration shall support local workspace deployment.

### R23.

Deployment operations shall be deterministic when deployment source resolution yields identical deployment artifacts.

### R24.

Identical deployment artifacts shall produce identical deployment metadata.

### R25.

Deployment shall be independent of execution planning.

### R26.

Deployment shall be independent of validation execution.

### R27.

Deployment outputs shall be consumable by validation planning frameworks.

### R28.

Deployment verification may include artifact validation, dependency validation, runtime validation, and environment validation.

### R30.

Deployment IDs shall be unique within the deployment registry.

### R31.

Deployment artifacts shall be isolated within a deployment workspace.

### R32.

Deployment verification shall produce a deployment verification outcome.

## Architecture Notes

### Deployment Source Modes

| Source Mode | Description |
|------------|------------|
| local_sync | Deploy from local workspace |
| git_branch | Deploy from repository branch |
| git_tag | Deploy from repository tag |
| git_commit | Deploy from repository commit |

### Deployment Model

```text
Deployment Source
        ↓
Source Resolution
        ↓
Artifact Acquisition
        ↓
Dependency Installation
        ↓
Runtime Preparation
        ↓
Deployment Verification
        ↓
Execution Ready Environment
```

Deployment Lifecycle

```text
PENDING
    ↓
DEPLOYING
    ↓
COMPLETED
```

State Description
PENDING Deployment queued, not yet started
DEPLOYING Deployment actively in progress
COMPLETED Deployment finished

Deployment Verification Outcomes

```text
READY
NOT_READY
PARTIAL
FAILED
```

Outcome Description
READY All verification stages passed; environment is execution-ready
NOT_READY One or more verification stages failed; environment is not usable
PARTIAL Some verification stages passed; environment may be usable with limitations
FAILED Verification could not complete; environment state is unknown

Deployment Workspace Model

```text
deployment_id/
    artifact/
    dependencies/
    runtime/
    verification/
    metadata/
```

Deployment artifacts shall be isolated within a deployment workspace. Each deployment operation receives its own workspace to prevent collisions.

Local Sync Example

```yaml
relix_tools:
  source_mode: local_sync
  local_path: ~/relix-tools
  deploy_path: /opt/relix-workspace/relix-tools
```

Git Tag Example

```yaml
relix_tools:
  source_mode: git_tag
  repo_url: git@github.com:org/relix-tools.git
  ref: rxta-v0.2.1
  deploy_path: /opt/relix-workspace/relix-tools
```

Git Commit Example

```yaml
relix_tools:
  source_mode: git_commit
  repo_url: git@github.com:org/relix-tools.git
  ref: 5f3a7c9
  deploy_path: /opt/relix-workspace/relix-tools
```

Version Independence Model

Relix and relix-tools version selection are independent.

Example:

```yaml
relix:
  ref: v0.2.1

relix_tools:
  ref: rxta-v0.2.4
```

The framework shall not assume:

```text
relix version == relix-tools version
```

Deployment Verification Model

Deployment verification may include:

```text
artifact validation
dependency validation
runtime validation
environment validation
```

Example verification activities:

```text
artifact presence validation
python runtime validation
dependency import validation
database connectivity validation
runtime readiness validation
```

Deployment Traceability

Deployment records shall contain:

```text
deployment_id
source_mode
source_reference
deploy_path
deployment_status
lifecycle_state
verification_outcome
```

Determinism Model

```text
Deployment Source
        ↓
Artifact Resolution
        ↓
Resolved Artifact
        ↓
Deployment
```

Determinism applies to the resolved deployment artifact.

Examples:

```text
git_commit → deterministic

git_tag → deterministic if tag resolves to same artifact

git_branch → deterministic only when branch resolution yields identical artifacts
```

Deployment Success Model

```text
Artifact Acquired
        ↓
Dependencies Installed
        ↓
Runtime Ready
        ↓
Verification Passed
        ↓
Execution Ready Environment
```

Deployment verification shall fail if any required verification stage fails.

Explicitly Forbidden

· Deployment performing execution planning
· Deployment generating execution_id
· Deployment modifying catalog metadata
· Deployment modifying benchmark selections
· Deployment modifying suite selections
· Deployment performing validation execution
