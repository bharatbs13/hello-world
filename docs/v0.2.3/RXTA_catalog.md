## D Profile Definition

D profiles are generated by the automation planner at runtime.
D identifiers (`depth_id`) are valid only within a single run.
Reports must include a run-level D mapping table.

### Naming Convention (frozen)

| Term             | Meaning                                | Example              |
|------------------|----------------------------------------|----------------------|
| depth_id         | Planner-generated profile identifier   | D1, D2, D3           |
| topology_shape   | Infrastructure topology classification | source_target        |
| infra_signature  | Concrete connector combination          | postgres_to_mysql    |

Note: The terms `depth_profile` and `depth_mode` are deprecated and must not appear in reports or code.

### Example Run-Level D Mapping

| depth_id | topology_shape | infra_signature        | source_connector | target_connector |
|----------|----------------|------------------------|------------------|------------------|
| D1       | source_target  | postgres_to_postgres   | postgres         | postgres         |
| D2       | source_target  | postgres_to_mysql      | postgres         | mysql            |
| D3       | source_target  | mysql_to_postgres      | mysql            | postgres         |
| D4       | source_target  | mysql_to_mysql         | mysql            | mysql            |

Note: depth_id values are not globally fixed. D1 in run A may differ from D1 in run B.
The mapping is always included in the run report.
